# `e / i / π` 联动敌人组

## 一句话

用欧拉公式 `**e^(iπ) = -1**` 当主题：一次「转半圈」在 `**π` 时刻**把局面**翻成反面**，再转半圈在 `**2π` 时刻**回到**开局状态**。

---

## 母题


| 符号    | 在主题里的意思                                 |
| ----- | --------------------------------------- |
| **e** | 基底、主输出与结算载体                             |
| **i** | 离开「实轴」——虚实两相，行为与收益随相位变                  |
| **π** | 「转到半圈」所需的进度——用计数 **t** 表示，不必在战斗里出现圆周率数字 |


战斗里 `**π` 一律用进度 `t` 表达**，避免玩家理解成几何题。

---

## 三条可执行规则

### 共享：旋转进度 `t`

- 首版定稿建议：`**t` 从 0 开始，**只由 `π` 自己行动时 +1**。
- `**t = 3`**：视为转到 `**π**` → 由 `**e` 触发一次「反转」**。
- `**t = 6`**：视为转到 `**2π**` → 由 `**e` 触发一次「归零」**。
- 如果之后改成全组共享每回合 +1，需要重新评估强度；不要让程序和策划各读一半。

### `π`：推周期

- **独有机制**：可以**指定一名敌人**，使其 **立刻结算当前行动并进入下一阶段**。
- 自身仍按上表推进 `**t`**。
- 首版中，`π` 是唯一稳定推进 `t` 的单位，因此它应是玩家可优先处理的时钟目标。

### `i`：虚实两相

- **没有传统护盾**；「防御」= **虚相**。
- **每被命中一次，切换实相 / 虚相**，并切换一版**行动意图**。
- **实相**：接近常规肉搏与直伤；**虚相**：伤害 / 控制 / 防御手段的**收益权重**按设计表变化。

### `e`：在 `t = 3` 与 `t = 6` 收割

4 个状态 （2 debuff/ 1 debuff 1 buff ..../ 2 buff）

- 平时正常攻防；**不强调随回合自然成长**，强调 `**t` 到点爆发**。
- 实装前必须把 Buff / Debuff 翻转表写死，不允许临场解释。

建议先用以下占位表定稿方向：

| `e` 身上状态 | `t = 3` 转移到主角侧 |
| --- | --- |
| 力量 +X | 虚弱 X 回合 |
| 格挡 / 防御强化 | 易伤 1 回合或下次受击增加 |
| 易伤 X | 主角获得小额增伤窗口 |
| 虚弱 X | 主角获得小额减伤或敌方降攻窗口 |

表格数值仍需调参，但映射方向必须固定。

`**t = 3` — 反转**

- 将 `**e` 当前身上的 Buff / Debuff 做一次「符号翻转」并转移到主角侧**。
- 示例：自身「力量+2」→ 主角「虚弱」2 回合；自身 2 层易伤 → 主角获得对应增益。
- 这是本组**最核心的联动结算**，具体映射用表固化，避免临场拍脑袋。

`**t = 6` — 回到原点**

- `**e` 的状态回到本场战斗开始时的初始状态**。

## 几何直觉

- 复平面上：乘 `**i`** ≈ 转 90°；累计到 `**π**` ≈ 半圈，落到**负实轴**；再到 `**2π`** 回到起点。

## 文档维护说明

当前建议首版采用：**仅 `π` 行动时 +1**。

如果未来改成全组共用一个 `t`，必须同步更新：

- `π` 的职责
- `e` 的反转频率
- `i` 的相位切换收益
- combat_analysis 的 encounter pressure review
